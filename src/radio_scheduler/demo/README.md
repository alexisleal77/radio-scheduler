# demo

Orchestrates already-implemented and already-tested public APIs
(`scenario_generator`-style hand-built `Scenario`s, `reference_implementations`,
`simulation_loop`, `benchmark`) to produce a small, demonstrable, reproducible
run of Round Robin, Proportional Fair, and MaxCQI over the same scenarios —
Delivery A of the HARNESS6G V21 integration (see
[`docs/design.md`](../../../docs/design.md) and
[`docs/proposal-traceability.md`](../../../docs/proposal-traceability.md)).

This module implements no scheduling or benchmarking logic of its own — see
`docs/architecture.md`'s "Extensibility over modification" principle and
`CLAUDE.md`'s thin-wrapper rule for `scripts/`.

## Contents

- `scenarios.py` — three small, hand-built `Scenario`s (`build_demo_scenarios()`),
  each chosen so the expected `AllocationDecision` set for every reference
  implementation can be computed by hand and asserted as an oracle in
  `tests/test_demo.py`: `ue_competition` (tied CQI, isolates each algorithm's
  own fairness/tie-break policy), `cqi_difference` (cold-start, isolates
  MaxCQI's CQI-driven pick from RR/PF's order-driven one), and
  `no_eligibility_or_resources` (the two distinct "zero decisions" boundary
  conditions — no eligible UE, and no Resource Block — that must never raise).
- `runner.py` — `run_demo()`: runs every (scenario, algorithm) pair through
  `simulation_loop.run()` for decisions and `benchmark.benchmark_run()` for
  computational cost, with an independent `initial_state()` per pair.
- `report.py` — `result_to_dict()` (structured, JSON-serializable view;
  `decisions_by_tti` groups `AllocationDecision`s for readability) and
  `render_report_pt()` (a Portuguese-language Markdown report), including this
  version's known, documented limitations (pipeline delay, buffer drain rule,
  HARQ, CQI-as-index, benchmark scope — never silently omitted).

## Running the demonstration

```
uv run python scripts/demo.py
```

Writes `evidence/demo/results.json` (structured data: scenario id, per-TTI
decision trace, full benchmark provenance/medians) and
`evidence/demo/relatorio.md` (the same content as a human-readable Portuguese
report) — both committed as evidence, regenerated by re-running the script.

## Status

Implemented (v0.1): three demo scenarios, oracle-based functional tests in
`tests/test_demo.py`, JSON + Portuguese report output. Scheduling-performance
metrics (throughput, fairness, packet latency) are not computed — see
`benchmark`'s own `README.md` for why.
